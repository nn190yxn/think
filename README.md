# 思想熔炉 Thought Forge

本地优先的 Windows 桌面应用。它把你日常的念头、观点、观察、一句话反复投入炉中，与多位大师的思维框架碰撞，产出可执行的判断，并把每一次判断沉淀为你的成长轨迹。

服务对象是「一个人的成长」。商业只是其中一个使用场景，投入的对象可以是任何一个念头、一段摘录、一个现象。

## 一、这是什么

一个人会读很多书、听很多访谈、看很多课程，但真正改变判断的往往不是「知道」，而是把同一个问题放到不同框架里反复对照。思想熔炉把这件手工活自动化了：

1. 把公开资料蒸馏成可调用的大师技能包，每位大师带有明确的判断框架、提问方式与表达风格。
2. 让多位大师围绕你的同一个问题独立作答，再交叉质询，收敛成可执行判断。
3. 把问题、判断、大师框架、原则、证据连成本地图谱，反复被唤起的关系被强化，长期沉寂的关系被衰减。
4. 在你没有主动提问时，也能基于新采集的内容与图谱变化主动推送碰撞结果。

界面不是一个问答框，而是同一连续空间的五个视点：

| 印记 | 境界 | 做什么 |
|---|---|---|
| 观 | 思维星图 | 你的念头在这里连成网络，激活与衰减都在观察之中 |
| 会 | 圆桌会诊 | 让骑士团从各层入场，隔离作答后再交叉质询 |
| 炼 | 蒸馏熔炉 | 把一位大师的语料炼成可调用的技能单元 |
| 藏 | 大师与资产 | 大师包、语料来源与知识地形的总账 |
| 我 | 成长与设置 | 演化长河、个人原则与这台炉子的所有开关 |

界面有两套主题，共用同一套设计令牌名，切换只改根元素的 `data-theme`：

- **窑变**：暗色，默认。
- **素瓷**：明色。

## 二、核心概念

### 层次轴：道、法、术、气、器、势

层次不是大师的身份标签，而是所有大师共同面对的六个问题。同一位大师可以同时声明多个层次。

| 层次 | 问题 | 承载什么 |
|---|---|---|
| 道 | 什么值得做 | 价值判断与世界观 |
| 法 | 规律是什么 | 体系与规律 |
| 术 | 具体怎么做 | 操作技法 |
| 气 | 靠什么心力度过 | 心力与状态 |
| 器 | 用什么载体放大 | 工具与载体 |
| 势 | 现在是不是时候 | 时机与环境 |

同一个真实问题通常同时命中多个层次，因此会诊强制跨层选角。每层有专属颜色与几何标记（点、方、三角、波纹、十字、双箭），颜色永远不是唯一通道，变化一律带文字标签。

### 圆桌会诊

大师库按「认知骑士团」组织：大师是常驻资产，话题是变量。一次会诊的动作顺序是

1. 按轮换策略从候选池选出席位。策略有三档：稳妥、碰撞、意外。
2. 每个席位锚定到六题中的一题，第一轮各自隔离作答，互不可见。
3. 第二轮起交叉质询，席位能看到他人发言，但共享背景对全部席位一致，席位自己的补充检索只出现在自己的提示词里。
4. 收敛为结论：分歧清单按题分组，并给出与上一次同主题会诊相比的立场变化（延续、调整、转向、新谈、停谈）。

缺口题有三种成因，界面上统一标为「这一题还要再谈」：该题无人站上、池中该题候选不足两位（凑不出同题对立）、上一轮在该题上没谈拢。种子库只有六位大师，术与势各只有一位，因此全新安装时默认缺口题是术与势。

### 思维网络

节点是认知单元，连线是认知关系（支持、冲突、衍生、类比、应用）。一次碰撞唤起的节点激活度上升，长期未被唤起则衰减；多次共同被唤起的连线权重上升。系统在空闲时固化：强化共激活连线、衰减弱连线、合并重复节点、识别矛盾，产出洞察。

### 双通道入库

大师入库有两条通道：手动导入大师包，以及主动搜集资料后蒸馏。主动搜集默认关闭，逐批确认后才入库。

## 三、需求全貌

三份规格合计 37 条需求，全部有对应的验收标准与实施任务。

### 基线 16 条（`thought-forge-workbench`）

1. 系统级感知：授权后记录剪贴板、前台窗口与文件活动，关闭即不产生记录。
2. Skill 与 AI 资产统计：识别本机 Skill 与已接入 AI 平台，按分类与领域统计。
3. 知识库统计与分类：建立来源目录的元数据索引，只读元数据不读正文。
4. 大师维度模型：领域 × 层次两轴定位，缺位时给出空缺提示与推荐蒸馏清单。
5. 大师蒸馏：把原始资料提炼为带触发条件与边界条件的可执行方法论。
6. 多大师会诊：隔离作答、交叉质询、收敛裁决。
7. 成长轨迹沉淀：每次会诊留档，包含问题、参与大师、各方判断、分歧点与结论。
8. 隐私与数据主权：数据默认只在本机，联网能力逐项开启。
9. 离线可用性：无网络时核心能力仍可用。
10. 思维网络：节点与连线、激活传播、时间衰减、固化调度。
11. 主动助学助理：用户未提问时基于新内容与图谱变化主动推送碰撞结果。
12. 迭代闭环：判断被复访、修正、提升为原则。
13. 认知骑士团与轮换：候选池、三种轮换策略、可整批换人。
14. 分层知识库：大师包、原始语料、动态信号、个人记录四部分。
15. 大师入库双通道：手动收录与主动搜集。
16. 大师包版本化与更新：带版本号，可回看历史快照。

### 深化 15 条（`2026-09-15-thought-forge-deepening`）

1. 自适应讨论轮次：轮次上限自适应，追加轮次单调增加。
2. 分歧度收敛曲线：逐轮给出分歧度并可视化。
3. 调参项：参数有边界，越界被拒。
4. 多跳激活传播：激活沿连线多跳扩散。
5. 认知聚类：固化时对图划分社区。
6. 模型链路真机验证方案：探针命令与退出码约定。
7. 逐席发言可见：每位席位的发言独立可见、可追溯。
8. 落点追问：对结论中的某一点追问，母会话不变、阵容继承。
9. 连接器：搜索、网页阅读、MCP 工具三类。
10. 会诊检索与检索快照：检索结果冻结进快照，可复现。
11. 检索安全与外部内容可信：发送前脱敏，可疑来源在提示词中被边界标记包裹。
12. 分歧判定可信：判定可核对，极性优先。
13. 成本与配额治理：调用以整数微元记账，配额生效。
14. 凭据、备份与复现：密钥只进系统凭据库，备份可校验、迁移前自动快照。
15. 自我约束与运行可恢复：回音可见、原则可撤销、中断可识别、取消保值。

### 六题会诊 6 条（`2026-09-17-thought-forge-six-questions`）

1. R1 六题档案：每位大师能看到自己在六题上的积累深浅，空缺题保留。
2. R2 大师层次声明：大师包声明它覆盖哪些层次。
3. R3 席位锚定到题：每个席位明确回答其中一题，圆桌与逐席发言口径一致。
4. R4 同题对立：对立度按题计算，只使用该题下的单元文本。
5. R5 按题换批补人：换批优先补缺口题，仍保持确定性与历史阵容不丢失。
6. R6 记录累积：同一主题多轮会诊时能看出每题立场的演化。

## 四、三条不可动摇的原则

这三条不是实现细节，改动它们等于改产品定义。

1. **本地优先**：数据默认只存本机。联网能力逐项开启、默认全关，每次开启都有审计与用途说明。无网络时核心能力仍可用。
2. **密钥不进数据库**：模型平台与连接器的密钥只交操作系统凭据库保管，数据库里只有引用名（如 `thought-forge/platform/{id}`、`thought-forge/connector/{id}`）。环境变量读取只作为回退路径。
3. **外部内容不可信**：检索回来的网页或工具结果一律视为不可信输入，发送前脱敏，可疑来源在提示词中被边界标记包裹，结论标注依据来源。

## 五、技术栈与架构

前端 React 19、TypeScript 5.9 严格模式、Vite 7、pnpm 10、Vitest 3。

Rust 侧分两个 crate：

- `thought-forge-core`：纯逻辑内核。数据库连接与迁移、设置、大师包校验、选角、会诊编排、思维网络、蒸馏状态机、采集归一化、成本记账、备份。不依赖任何界面系统库，可以在无 WebView 环境下直接 `cargo test`。
- `thought-forge-desktop`：Tauri 2 桌面外壳。类型化 command 边界、系统凭据库、剪贴板与前台窗口探针、文件监听、连接器注入、自动更新。

数据存储是单文件 SQLite（rusqlite，bundled，含 FTS5），迁移版本化，当前 17 个迁移。

前后端之间是类型化 command 边界：统一返回 `{ok:true,data}` 或 `{ok:false,code,message}`。错误码清单由 Rust 侧用例读取前端 `src/ipc/protocol.ts` 逐项比对，新增内核错误变体必须同时改三处，否则用例失败。当前注册 131 个命令。

采集职责边界：外壳只产 `RawSample`，脱敏、去重、合并、落库全部由内核 `capture::pipeline` 负责。

## 七、快速开始

### 环境要求

Windows 是本项目的目标平台。开发至少需要：

- Rust stable 1.85 或更高。依赖树包含 edition 2024 的 crate，旧版本会在下载依赖阶段就报 `feature edition2024 is required`。
- Visual Studio 2022 的「使用 C++ 的桌面开发」工作负载，提供 MSVC 链接器。
- Node 20 或 22。
- pnpm 10.34.5，用 `corepack prepare pnpm@10.34.5 --activate` 激活。不要用 `npm i -g pnpm` 覆盖 corepack 垫片。
- WebView2 运行时。Windows 11 与较新的 Windows 10 自带。
- WiX Toolset，生成 MSI 时需要。

在 Linux 上开发前端与内核是可行的，只需要额外装 `libwebkit2gtk-4.1-dev`、`libgtk-3-dev`、`libayatana-appindicator3-dev`、`librsvg2-dev`、`libxdo-dev`、`pkg-config` 才能编译桌面外壳。Debian 12 用 `apt-get install -y --no-install-recommends`。

### 安装与运行

```bash
# 安装前端依赖
pnpm install

# 只跑前端，用于界面开发
pnpm dev

# 跑完整的桌面应用
pnpm tauri:dev

# 生成 Windows 安装包（NSIS 与 MSI）
pnpm tauri:build:windows
```

前端开发服务器端口固定 1430，配了 `strictPort`，被占用会直接失败。

### 质量门禁

每次改动后按顺序跑完这四组，全绿才算完成一个阶段：

```bash
# 前端
pnpm typecheck
pnpm test
pnpm build

# Rust 内核
cd src-tauri
cargo test -p thought-forge-core
cargo test -p thought-forge-core --examples
cargo clippy -p thought-forge-core --all-targets -- -D warnings

# Rust 桌面外壳
cargo test -p thought-forge-desktop --lib
cargo clippy -p thought-forge-desktop --all-targets -- -D warnings
```

两点约定：

- 内核的 `tests/network_perf.rs` 会建十万节点的库，`cargo test -p thought-forge-core` 会把它一起跑。只想跑单项用 `--test <模块名>`。
- 项目不使用 rustfmt 门禁。core crate 未采用 rustfmt 约定，`cargo fmt -- --check` 会报大量既有漂移，不要为了让它通过做全量空格级改动。

发布前还有一道静态检查，占位配置下会以退出码 1 失败，属预期：

```bash
pnpm check:release-config
```

### 云端 Windows 验收

`.github/workflows/verify-thought-forge-windows.yml` 在 GitHub 的 `windows-latest` 真机上跑不需要密钥的验收项，手动触发。它覆盖桌面壳在 Windows 上编译并跑通全部用例、NSIS 与 MSI 的静默安装启动卸载、以及内核的备份与迁移用例，并会用只读检查器校验应用真实建出的数据库。

它判不了的项（交互桌面采集、界面回填、发言质量、提示词隔离、自动升级等）见 `HANDOVER.md` 与 `.monkeycode/specs/2026-09-15-thought-forge-deepening/windows-verification.md`。

### 发布

`.github/workflows/release-thought-forge.yml` 在打标签后构建并发布安装包。它需要仓库配置两个密钥：`TAURI_SIGNING_PRIVATE_KEY` 与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。当前 `tauri.conf.json` 的 `pubkey` 与 `updater.endpoints` 仍是占位值，换成本次发布真正要用的公钥与托管域名之前，发布流程会被那道检查挡住。

## 八、数据与隐私

应用数据目录是 `%APPDATA%\com.thoughtforge.desktop\`，数据库是其中的 `forge.db`。应用启动时在这一步建库并执行迁移，因此「启动后出现该文件」可以同时证明 WebView2 初始化成功与迁移跑通。

密钥的本体不存在数据库里，只存在系统凭据库。备份用 `VACUUM INTO` 生成，恢复前先校验完整性，迁移前会自动留下一份 `pre_migration` 快照。

只读检查器 `src-tauri/crates/core/examples/forge_verify.rs` 可以随时核对数据库形状，它以只读模式打开，不会改动任何数据：

```powershell
cargo run -p thought-forge-core --example forge_verify -- $env:APPDATA\com.thoughtforge.desktop\forge.db
```

退出码 `0` 表示无未过项（跳过不计为失败），`1` 表示存在未过项，`2` 表示用法或库路径错误。参数与逐项判据见 `windows-verification.md`。
