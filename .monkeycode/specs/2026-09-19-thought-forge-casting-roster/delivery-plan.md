# 交付规划：假设 Alex 是甲方（2026-09-19）

## 一、立场

把软件当商品交出去，甲方只问四件事：**能装上吗、装上会用吗、用起来出问题怎么办、以后怎么升级。**
现在这四件事的答案分别是：**没试过、没有说明、没办法自救、没有路径。** 功能不缺，缺的是最后一公里。

## 二、交付视角的缺口（按"甲方会不会卡住"排序）

### A. 装不上（最高优先级）

1. **没有验证过的安装包**：NSIS 与 WiX 的安装、自动升级、签名都没在真机上验过（P16.9）。
2. **签名证书未知**：没有证书就出不了"签名版"，Windows 会弹未知发布者警告。要么你提供证书，要么明确接受并写进安装说明。
3. **CI 没在云端跑过**：本地三套门禁全绿，但 GitHub 上的流水线我从没见它成功执行。交付前必须确认，否则"在我机器上能跑"这句话没有保障。

### B. 装上不会用

4. **首启体验未验证**：新装的机器上，六个种子大师包是否自动就位？**没确认过。** 如果没自动装，甲方打开看到的是一个空名册——这会直接判定为"没做好"。
5. **没有用户手册**：现有 README 与 HANDOVER 都是给开发看的，满屏术语。甲方要的是《从安装到第一场会诊》。
6. **体检清单只报不导**：`「我」→ 系统` 的六项体检能告诉甲方"联网没开、密钥没配"，但**每一项没有"去哪里配"的按钮**，甲方得自己找。

### C. 出问题没法自救

7. **没有诊断包导出**：出问题时甲方无法一键打包版本号、日志摘要、配置状态发给你（不含密钥）。这一项此前明确"本轮不做"，交付前建议补上。
8. **中断恢复可见性不足**：内核支持中断续跑，但甲方不知道在哪儿看、怎么续。
9. **换机没有说明**：备份能做，但没有一页讲清"换电脑：旧机备份 → 新机恢复 → 凭据库要重录"。

### D. 长期

10. **没有检查更新**（此前明确不做）：可以不做，但必须在手册里写清手动升级步骤。
11. **名册只有 6 位、且术与势各只有一位**：选角在这两题永远凑不出对立面。要交付"能碰撞"的体验，名册必须扩。
