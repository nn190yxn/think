# 蒸馏计划：20 位名册（2026-09-19 起，2026-09-21 按仓颉流程修订）

## 〇、这次和仓颉的原版有什么不同（Alex 2026-09-21 定）

仓颉的产出是**一组可调用的 skill**（`SKILL.md` + `test-prompts.json` + 安装进 skills 目录）。

**我们不要 skill。** 我们要的是**对一位大师的完整了解**——他的框架、原则、案例、反例、术语，落成这个软件真正能用的东西：`master.json` 的六题单元 + `corpus/notes.md` 的带出处语料。

借的是它的**方法**，不是它的**产物形态**：

| 仓颉阶段 | 我们的做法 | 产出 |
|---|---|---|
| 阶段 0 整书理解（Adler 四步） | 对该大师公开材料做整体理解 | `MASTER_OVERVIEW.md` |
| 阶段 1 五路并行提取 | 框架 / 原则 / 案例 / 反例 / 术语 | `candidates/*.md` |
| 阶段 1.5 三重验证 | 跨域佐证 / 预测力 / 独特性 | `verified.md` + `rejected/*.md`（留审计） |
| 阶段 2 RIA++ 构造 | **不写 SKILL.md**，写六题单元 | 并进 `master.json` 的 `units` |
| 阶段 3 术语与互链 | 不建 skill 索引，整理术语与单元间关系 | `GLOSSARY.md`（互链写进单元说明） |
| 阶段 4 压力测试 | 不做 skill 触发测试，做**选角测试** | `selection-cases.md`（该出手/不该出手/边界模糊） |
| 阶段 5 交付 | 不安装 skill；交付物是**理解成果** | 更新后的 `master.json` + `corpus/notes.md` |

RIA++ 六段与我们单元字段的对应：

| RIA++ | 单元字段 |
|---|---|
| R 原文引用（≤150 字/段，带出处） | `evidence.excerpt` + `evidence.location` |
| I 用自己的话重写方法论骨架 | `mechanism` |
| A1 作者亲自用过的案例 | `evidence` |
| A2 未来触发（什么情境下需要它） | `triggerCondition` |
| E 可执行步骤 1-2-3 | `steps` |
| B 边界（什么时候不适用） | `boundary` |

## 一、为什么要"整体"计划

蒸馏不是"每人跑一遍流水线"。现有六位**每人只有 2 条单元、六题里有 4 题是 0**；此时急着加 14 位新人，只是把"空的名册"从 6 个变成 20 个。所以顺序是**先补薄、再增人**。

## 二、每人要做到什么程度（准入门槛）

1. **材料**：公开可追溯（演讲 / 访谈 / 书籍 + 出处），入库到原始语料层。
2. **单元**：六题**各至少 1 条**；每人目标 8–14 条，其中至少 2 条带明确触发条件与边界条件。
3. **验证**：每条单元过三重验证（跨域佐证 / 预测力 / 独特性），未过的进 `rejected/` 并写原因。
4. **声明**：`master.json` 的 `layers` 与实际单元一致，不虚报层次。
5. **体检**：六题档案无 0；若某题确实无料，明确写清"此人此题不设单元"而不是留空。
6. **选角**：用他真做一次，看输出像不像这个人；再看系统是否把该出手的单元选了出来。

## 三、分工

- **我做**：全网检索公开材料 → 五路提取 → 三重验证 → 起草单元与语料（逐条标来源）→ 出六题体检与缺口报告。
- **你做**：定"收谁不收谁"、审内容像不像本人、决定哪些私料进库、需要书籍时提供材料。
- **不做**：不替你编造某人的观点；缺料如实留空并标缺口。

## 五、每一步怎么验收（都能核对）

1. **材料入库**：`corpus` 里能看到条目与来源；工作目录里有 candidates 与 rejected 的审计轨迹。
2. **蒸馏完成**：阶段 0–4 产物齐全，六题各至少 1 条单元。
3. **体检通过**：名册里该大师六题无 0（或写明已知缺口）。
4. **选角像本人**：一次真机的三席会诊，你能认出"这是他的主张与口气"。
5. **归档**：本次补料写进任务清单与 README，留下可回看的记录。
