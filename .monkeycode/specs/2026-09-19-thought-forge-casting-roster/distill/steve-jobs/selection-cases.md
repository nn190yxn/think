# 阶段 4：选角测试用例（乔布斯）

## 一、该出手的

| 提问 | 期望选出的单元 |
|---|---|
| 我们产品线有九条，每条都有人做，但都做不精。 | 聚焦即说不 |
| 用户总说我们这里不好用，那是另一家的模块。 | 端到端体验 |
| 技术团队说这个体验做不出来，要两倍预算。 | 从用户体验倒推技术、现实扭曲力场 |
| 团队最近泄气，觉得目标定得太高。 | 现实扭曲力场（须同时提示边界：高压的代价） |
| 我要不要招一批"够用"的人先把活干起来。 | A 级人才小团队 |
| 现在这个市场很热闹，我要不要挤进去。 | 在技术转折点重新定义品类 |

## 二、不该出手的（诱饵）

| 提问 | 为什么不该由他出手 |
|---|---|
| 帮我做一份合规审计清单。 | 合规要求稳定与可追溯，与"聚焦砍掉"的方法相反 |
| 团队氛围差，怎么改善关系。 | 他的方法在人际关系上是反面教材（传记有明确记载） |
| 明天汇报穿什么。 | 常识级问题 |

## 三、边界模糊的

| 提问 | 判定要点 |
|---|---|
| 我该不该砍掉一条还在赚钱的老业务。 | 该触发「聚焦即说不」，但须提示边界：守成型业务的收缩要权衡存量客户 |
| 我想让团队"拼一把"，冲刺一个激进目标。 | 该触发「现实扭曲力场」，但必须同时给出代价提示（人才流失与伦理边界） |
| 这个功能用户没提，我要不要做。 | 该触发「从用户体验倒推技术」，边界在于：用户没提不等于用户不需要，要看是不是体验断裂 |

## 四、跨同门混淆

| 提问 | 容易混淆 | 正确判断 |
|---|---|---|
| 我方向太多了，不知道砍哪个。 | 聚焦（术）vs 连点成线（道） | 该砍就选聚焦；只是纠结过去经历有用没用，选连点成线 |
| 我们该自己做一个组件，还是买现成的。 | 端到端（术）vs 从用户体验倒推（法） | 涉及体验关键环节选端到端；涉及功能该不该做选倒推 |
| 我觉得自己什么都会一点，但都不精。 | A 级人才（器）vs 求知若饥（气） | 若问题是团队标准，选 A 级人才；若问题是自己的状态，选求知若饥 |
